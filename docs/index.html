The Problem

Teams ship prompt changes blind.

You tweak a system prompt to fix a customer complaint. You swap a model version for better benchmarks. You add new test cases to cover an edge case. Everything looks fine in staging. Then users start reporting wrong answers, and you have no idea which change caused it.

The core issue: LLM features are messy. A prompt change, a model update, a dataset tweak, any of them can quietly break what was working yesterday. You do not find out until users start complaining. And by then, you have already shipped a dozen more changes on top.

!
No safety net
Prompt changes go straight to production. No validation, no comparison, no gate. You find out about regressions from support tickets.
?
Unclear signal
When quality drops, you do not know which change caused it. Prompt? Model? Dataset? You guess, roll back, and hope.
--
Slow detection
Gradual decline is invisible. A 1-point drop per week looks like noise until you realize you have been degrading for a month.

The Approach

CI/CD for model behavior.

What if you could run a versioned prompt against a labelled golden set, score every response, and compare the result to a stored baseline, all inside your CI pipeline? That is MRDS. It treats model behavior the same way CI treats code: test it, compare it, gate it.

Design Decision

Why we track slow drift separately.

A single run can miss gradual decline. If your model drops 1 percentage point per week, each individual run looks like noise. But over a month, you have lost 4 points and nobody noticed.

That is why MRDS maintains two separate signals: per-run regression detection (catches sudden breaks) and a 7-run moving average (catches the slow slide). The moving average alerts when the trend drops below a configurable delta compared to the first run.

!
Per-run regression

Catches sudden breaks. A single bad deploy, a prompt that catastrophically fails, a model update that breaks everything.

Run 7: CRITICAL (sudden drop detected)

--
Slow drift (7-run MA)

Catches gradual decline. Each run looks fine, but the trend is consistently downward. This is the dangerous one.

7-run MA: SLOW_DRIFT_WARNING (trend detected)

Per-run regression detection tells you if you broke something today. Drift detection tells you if you are slowly breaking something over time. You need both, because the slow slide is the one that ships to production for weeks before anyone notices.

Quickstart

Up and running in minutes.

# Install dependencies
$ pip install -r requirements.txt
 
# Run the test suite (79 tests)
$ python test_mrds.py
 
# Run the golden set with mock provider
$ python runner.py --provider mock --no-judge
 
# Set a baseline for future comparisons
$ python runner.py --set-baseline --force
 
# Run with a live provider (e.g. Ollama)
$ python runner.py --provider ollama --concurrency 8
