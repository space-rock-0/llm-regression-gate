The Problem

LLM features break silently.

Prompt changes
A tweak to the system prompt can shift model behavior in ways you do not catch until users report wrong answers.
Model updates
Swapping a model or updating its version can degrade output quality on inputs that used to work fine.
Dataset drift
Adding or removing test cases changes the distribution. A metric that looked fine last week can hide a real regression today.
THE PROBLEM 02 / 14
The Idea

Versioned prompts. Labelled data. Baseline diff.

Run a versioned prompt against a human-labelled golden set. Score every response. Compare the result to a stored baseline. Get a verdict: PASS, WARN, or CRITICAL_REGRESSION.

THE IDEA 03 / 14
Architecture

How MRDS works

1
Prompt versioning
Each prompt lives in a YAML file (prompts/v1.yaml, v2.yaml). The contract layer enforces the label set and prompt construction rules.
2
Async evaluation engine
167 golden test cases run through asyncio with a semaphore-bounded concurrency. Two transports: httpx for OpenAI-compatible APIs, wrapped clients for sync providers.
3
Baseline comparison
Metrics are scoped to provider:prompt_version:dataset_version. A dataset edit repoints baselines automatically. No manual cleanup needed.
4
Reporting and alerts
HTML report with full run details. Slack notifications via Block Kit. Drift detection over a 7-run moving average.
ARCHITECTURE 04 / 14
Scoring

What we measure

Exact match
Primary signal. Compares model output labels against hand-labelled ground truth. LLM-as-Judge degrades gracefully but the verdict stays anchored to exact match.
Summary quality
LLM-as-Judge scores summary outputs when exact match is not applicable. Runs async, never fails the run.
Latency
Per-call response time tracked across the golden set. A sudden spike can signal infrastructure issues before users notice.
Token usage
Prompt and completion tokens split by classify vs judge. Reported per run so cost changes are visible.
SCORING 05 / 14
Verdicts

Three levels of signal

PASS
Drop is within noise thresholds (default: 3 percentage points). Ship it.
WARN
Drop exceeds the warning threshold. Look before shipping. Named flips tell you which cases changed.
CRITICAL_REGRESSION
Drop exceeds the critical threshold (default: 8 percentage points). Blocks merge in CI.

Thresholds are configurable via WARN_THRESHOLD and CRITICAL_THRESHOLD environment variables.

CI GATE 07 / 14
Drift

Catches slow degradation

A single run can miss gradual decline. MRDS tracks a 7-run moving average and alerts when the MA drops beyond the configured delta compared to the first run. This catches the slow slide that a one-off diff would never flag.

DRIFT DETECTION 08 / 14
Decisions

Design choices

Hand-labelled ground truth
Labels are the oracle. LLM-generated labels would make the judge and the subject the same system.
Deterministic mocking
CI runs no live LLM. Mock provider honours the prompt label set. PR checks stay under 30 seconds.
Dataset-scoped baselines
Changing the dataset version invalidates prior baselines. No stale comparisons.
Contract is the swap seam
Providers swap without touching the evaluator. The contract layer is the only boundary.

RESULTS 10 / 14
Stack

Built with Python

asyncio + httpx
Async batch execution with semaphore-bounded concurrency. Two transports behind one contract.
Pydantic
Typed input and output at the contract boundary. Invalid shapes cannot be constructed.
SQLite
Stdlib storage with JSON fallback. No ORM. Runs anywhere Python runs.
Docker
Dockerfile and docker-compose included. Thresholds configurable via environment variables.
TECH STACK 11 / 14
Quickstart

Up and running in minutes

# Install dependencies
$ pip install -r requirements.txt
 
# Run the test suite (79 tests)
$ python test_mrds.py
 
# Run the golden set with mock provider
$ python runner.py --provider mock --no-judge
 
# Set a baseline for future comparisons
$ python runner.py --set-baseline --force
 
# Run with a live provider (e.g. Ollama)
$ python runner.py --provider ollama --concurrency 8
