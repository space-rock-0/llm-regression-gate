class EmailInput(BaseModel)
Description

One support email, typed.

A bare str would be simpler, but metadata then travels as a parallel dict that can drift out of sync with the text. Carrying subject and id inside the model means the pipeline can join predictions back to the dataset row without anyone passing two objects around together.

Fields
NameTypeDescription
email_idstrDataset row id, for traceability. Default: ""
subjectstrEmail subject line, optional. Default: ""
bodystrRaw email text from the customer. Required
Raises
  • ValueError - body is empty, nothing to classify.

class PromptConfig(BaseModel)
Description

THE CONTRACT the eval pipeline consumes.

A prompt spec (what the YAML file says) plus everything the pipeline must enforce: which labels this version may emit, how the prompt is assembled, and that the model answer is valid before anyone sees it.

class ContractViolationError(ValueError, RuntimeError)
Description

The model, or a caller, produced something the contract forbids.

Inherits from both ValueError and RuntimeError so older call sites that caught either still work. It is raised at the boundary, once, instead of being checked inline in five different places.

classifier.py
classify_email(email_body, prompt=None, client=None, prompt_version=None) -> dict
Description

Classify one support email.

One function does the whole job. A regression is a change in the OUTPUT of this function. If the behaviour lived in 6 classes with hidden state, a diff in behaviour would be impossible to attribute. One function, no hidden state, pure input to output is what makes the later "compare against baseline" step trustworthy.

Args
NameTypeDescription
email_bodystr | EmailInputRaw email text, or an EmailInput carrying subject/id.
promptPromptConfig | PromptSpec | NoneA PromptConfig (contract) or a bare PromptSpec. Omit to load YAML.
clientChatClient | NoneLLM client. Omit to resolve one from env vars (mock default).
prompt_versionstr | NoneWhich prompt file to load. Omit for resolve_version().
Returns
dict - {"category": str, "summary": str, "provider": str, "prompt_version": str}
Raises
  • ContractViolationError - blank email, unparseable model output, invalid label.
  • RuntimeError - provider failed to start or is unreachable.

class MockClient
Description

Fake LLM. Answers with fixed keyword rules. Never calls a network.

Default provider. Deterministic, offline, free. A regression-detection system needs a ground truth that NEVER moves.

get_client(provider=None) -> ChatClient
Description

Build the LLM client. Resolution order: explicit argument > PROVIDER env > USE_MOCK env > mock (safe default).

Mock is the fallback because MRDS must run in CI with no keys and no network. A missing key should degrade to a deterministic run, not a crash.

Raises
  • ValueError - unknown provider name.
  • RuntimeError - SDK not installed or API key missing.

storage.py
class SQLiteStore
Description

One backend: SQLiteStore using stdlib sqlite3. Real queries, real durability.

Why stdlib sqlite3 and no ORM: an ORM adds a dependency and a layer of mapping code that a beginner then has to learn before understanding the data. For 3 tables, plain SQL is clearer about what actually happens.

Schema
-- Tables runs (run_id, created_at, provider, prompt_ver, dataset_version, n_samples, accuracy, metrics_json) predictions (run_id, sample_id, category, expected, correct, summary) baseline (key, run_id, created_at, accuracy, metrics_json) case_metrics (run_id, sample_id, metrics_json)
Methods
MethodDescription
save_run(run, predictions)Persist a run and its predictions.
get_run(run_id)Fetch one run by ID.
list_runs()List all runs ordered by created_at.
get_predictions(run_id)Fetch predictions for a run, including case_metrics.
set_baseline(key, run)Pin a run as the baseline for a key.
get_baseline(key)Fetch the baseline for a key.
close()Close the SQLite connection.
